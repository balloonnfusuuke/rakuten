ConnorsRSI(2) 自動監視システム
設計書 v1.0  ―  日中最高値キャプチャー対応版
1. プロジェクト概要
1.1 課題と目的
現状の ConnorsRSI(2) 運用では「終値での売却」のみを行っているため、日中に発生する一時的な高値（スパイク）を取りこぼすケースが多発している。本システムは以下を実現する。
従来の課題
本システムで解決
終値売りのみ → 日中高値を取りこぼす
リアルタイム価格監視で日中ピークを捕捉
手動でTradingViewをチェック
月曜スクリーニング → 自動ウォッチリスト登録
売りタイミングが感覚的
RSIベースの出口アルゴリズムで規律ある決済
複数銘柄の同時管理が困難
ダッシュボードで一元管理・アラート通知
1.2 システム全体像
アーキテクチャ概要
[ TradingView ]  →  [ スクリーナーモジュール ]  →  [ ウォッチリストDB ]
↓
[ 価格フィード API ]  →  [ リアルタイム監視エンジン ]  →  [ 出口判定ロジック ]
↓
[ 通知エンジン ]  →  [ ダッシュボード UI ]  →  [ トレード履歴 ]
2. ConnorsRSI(2) 戦略ロジック
2.1 指標定義
ConnorsRSI は Laurence Connors が開発した複合 RSI 指標。本戦略では期間 2 を使用。
コンポーネント
パラメータ
説明
RSI
期間 = 2
短期 RSI（2日）で過売・過買を計測
StreakRSI
連勝/連敗 RSI
連続上昇または下落日数に対する RSI
PercentRank
期間 = 100
直近100日の騰落率のパーセンタイル順位
ConnorsRSI
= 平均(3値)
上記3指標の単純平均
// ConnorsRSI 計算式
ConnorsRSI(2) = ( RSI(2) + RSI(Streak, 2) + PercentRank(100) ) / 3
// エントリー条件
BUY  : ConnorsRSI(2) < 10  AND  Price > 200DMA  AND  Volume > 平均出来高
// 出口条件（本システムで拡張）
EXIT : ConnorsRSI(2) > 70  OR  Intraday High Target Hit  OR  Stop Loss
2.2 エントリーシグナル（月曜スクリーニング）
ConnorsRSI(2) < 10（強い過売り状態）
終値 > 200日移動平均（上昇トレンド銘柄のみ）
当日出来高 > 20日平均出来高の 1.5 倍（流動性確保）
株価 $5 以上・時価総額 $500M 以上（低流動性除外）
TradingView スクリーナーで毎週月曜 10:00 自動実行
2.3 出口戦略アルゴリズム（本システムの核心）
従来の「終値売り」を廃止し、以下の階層型出口戦略を採用する。

2.3.1 日中高値キャプチャーアルゴリズム
目的
エントリー後の初動上昇を最大限に取得する。終値を待たず、日中の価格スパイクで利確する。
// 動的ターゲット計算
base_target  = entry_price * (1 + target_pct)
target_pct   = clamp(atr_pct * multiplier, min_pct, max_pct)
// デフォルトパラメータ
atr_period   = 2          // ATR期間
multiplier   = 2.0        // ATR倍率
min_pct      = 0.02       // 最小目標: +2%
max_pct      = 0.08       // 最大目標: +8%
// 監視ループ（5秒間隔）
while position_open:
current_price = get_realtime_price(symbol)
if current_price >= base_target:
execute_limit_sell(symbol, current_price)
send_alert('TARGET HIT', symbol, current_price)

4.2 監視エンジン 詳細フロー
処理間隔
リアルタイム価格受信は WebSocket（遅延 < 100ms）。出口判定ループは asyncio で並列処理（5秒間隔）。
async def monitor_loop(watchlist: List[Position]):
async with price_feed.connect() as feed:
await feed.subscribe([p.symbol for p in watchlist])
async for tick in feed:
position = find_position(tick.symbol)
if not position: continue
# Priority 1: Stop Loss
if tick.price <= position.stop_price:
await order_manager.market_sell(position, 'STOP_LOSS')
await notifier.alert(' 損切り', position, tick.price)
# Priority 2: Intraday Target
elif tick.price >= position.target_price:
await order_manager.limit_sell(position, tick.price, 'TARGET_HIT')
await notifier.alert(' 目標到達', position, tick.price)
# Priority 3: Volatility Exit (partial)
elif is_high_volatility(position) and tick.rsi > 50:
await order_manager.partial_sell(position, 0.5, 'VOLATILITY')
await notifier.alert(' 部分利確', position, tick.price)

5.2 TradingView Pine Script アラート設定
TradingView 側でも補完的にアラートを設定することで、スクリーナー間の空白時間をカバーする。
// Pine Script v5 - ConnorsRSI(2) Alert
//@version=5
indicator('ConnorsRSI(2) Monitor', overlay=false)
// ConnorsRSI計算
rsi2 = ta.rsi(close, 2)
streak = 0.0
streak := close > close[1] ? (streak[1] > 0 ? streak[1] + 1 : 1) :
close < close[1] ? (streak[1] < 0 ? streak[1] - 1 : -1) : 0
streakRSI = ta.rsi(streak, 2)
prank = ta.percentrank(ta.roc(close, 1), 100)
crsi = (rsi2 + streakRSI + prank) / 3
// アラート条件
buySignal  = crsi < 10 and close > ta.sma(close, 200)
exitSignal = crsi > 70
alertcondition(buySignal,  'BUY',  'ConnorsRSI BUY: {{ticker}} @ {{close}}')
alertcondition(exitSignal, 'EXIT', 'ConnorsRSI EXIT: {{ticker}} @ {{close}}')

10.2 分析エンジン実装
# analysis/trade_analyzer.py
import pandas as pd
import sqlite3
from dataclasses import dataclass
class TradeAnalyzer:
def __init__(self, db_path: str):
self.conn = sqlite3.connect(db_path)
def load_closed_trades(self) -> pd.DataFrame:
query = '''
SELECT symbol, entry_price, exit_price, entry_date, exit_date,
exit_reason, crsi_at_entry, shares,
(exit_price - entry_price) / entry_price AS return_pct,
(exit_price - entry_price) * shares AS pnl
FROM watchlist WHERE status = 'CLOSED'
'''
return pd.read_sql(query, self.conn)
def summary_stats(self, df: pd.DataFrame) -> dict:
wins = df[df['pnl'] > 0]
losses = df[df['pnl'] <= 0]
return {
'total_trades'    : len(df),
'win_rate'        : len(wins) / len(df) * 100,
'avg_win_pct'     : wins['return_pct'].mean() * 100,
'avg_loss_pct'    : losses['return_pct'].mean() * 100,
'profit_factor'   : wins['pnl'].sum() / abs(losses['pnl'].sum()),
'expected_value'  : df['pnl'].mean(),
'avg_hold_days_w' : (wins['exit_date'] - wins['entry_date']).dt.days.mean(),
'avg_hold_days_l' : (losses['exit_date'] - losses['entry_date']).dt.days.mean(),
}
def exit_reason_breakdown(self, df: pd.DataFrame) -> pd.DataFrame:
"""出口理由ごとの勝率・平均リターン分析"""
return df.groupby('exit_reason').agg(
count    = ('pnl', 'count'),
win_rate = ('pnl', lambda x: (x > 0).mean() * 100),
avg_pnl  = ('pnl', 'mean'),
avg_ret  = ('return_pct', lambda x: x.mean() * 100)
).round(2)
def crsi_bucket_analysis(self, df: pd.DataFrame) -> pd.DataFrame:
"""エントリー時ConnorsRSI値を0-2/2-5/5-10にバケット分割して勝率比較"""
df['crsi_bucket'] = pd.cut(df['crsi_at_entry'], bins=[0,2,5,10],
labels=['0-2','2-5','5-10'])
return df.groupby('crsi_bucket').agg(
count    = ('pnl','count'),
win_rate = ('pnl', lambda x: (x>0).mean()*100),
avg_ret  = ('return_pct', lambda x: x.mean()*100)
).round(2)
